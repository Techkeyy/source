# Source deployment preparation

This document records Source's Render deployment configuration. The application is deployed as a paid Render Web Service using the lowest practical paid plan, while MongoDB Atlas and DeepSeek remain external server-side dependencies.

## Render service

render.yaml defines one full Next.js web service:

- Build: npm ci && npm run build
- Start: npm run start
- Health check: /
- Runtime: Node.js
- Node version: 24.21.0
- Compute plan: `0.5c-512mb` (Render's current paid equivalent of Starter)
- Secrets are either prompted with sync: false or generated by Render with generateValue: true

The service is a web service because Source uses server-side authentication, MongoDB access, website extraction, and DeepSeek calls. It must not be configured as a static export.

At initial Blueprint creation, provide:

1. MONGODB_URI for the Atlas application user.
2. `DEEPSEEK_API_KEY` for the server-side DeepSeek call, with
   `INFERENCE_PROVIDER=deepseek` and `DEEPSEEK_MODEL=deepseek-flash`.
3. NEXT_PUBLIC_APP_URL after Render provides the service URL, for example https://source-example.onrender.com.
4. Optional SERPAPI_KEY and SENTRY_DSN only when the owner chooses to enable those integrations.

SESSION_SECRET is generated by Render in the Blueprint. Never copy a local .env.local secret into source control or the browser. The DeepSeek key remains a Render server-side secret and is never exposed to the client.

## MongoDB Atlas networking

Create a least-privilege Atlas application user and use the Node MongoDB driver connection string. In Atlas Network Access, add the Render service outbound IP addresses documented for the deployed service. Do not use 0.0.0.0/0 as a shortcut for production. Choose an Atlas region close to the selected Render region to reduce latency.

The owner must confirm the Atlas cluster accepts the Render service IP range before production UAT. The repository cannot infer the correct outbound range before the Render service exists.

## GitHub handoff

Before publishing:

- Create the repository as private or public according to the owner’s submission plan.
- Push package-lock.json, source, render.yaml, and documentation.
- Verify .env.local, .env, and other ignored local configuration files are not tracked.
- Add repository URL and commit SHA to the final acceptance record.
- Configure Render to build from the intended default branch.

No GitHub repository or push was performed during this preparation phase.
